# Quant Portfolio Optimization Engine — Master Plan

## Product vision

Build a modular quantitative research and portfolio analytics platform that can ingest market data, calculate financial statistics, optimize allocations under explicit constraints, analyze risk, and evaluate strategies with reproducible backtests. The product supports research and decision support; it must not imply that estimated returns or backtests guarantee future performance.

## Architecture principles

- Modular monolith first; do not start with microservices.
- API-first backend with versioned routes.
- Provider-neutral market-data interfaces.
- Quantitative calculations reside in tested Python modules, not frontend code.
- Explicit data-quality rules; never silently fabricate data.
- Record dataset versions, assumptions, constraints, and software/model versions.
- Add infrastructure only when requirements justify it.
- Design for US and PSX markets without assuming identical calendars, identifiers, data rights, or provider coverage.

## Recommended technology

- Backend: Python 3.11+, FastAPI, Pydantic
- Data processing: pandas, NumPy
- Optimization later: SciPy and/or CVXPY; evaluate solver suitability and licensing before selecting a production solver
- Testing: pytest, HTTPX
- Frontend later: React, TypeScript, Vite, Tailwind CSS, shadcn/ui, Plotly
- Persistence later: PostgreSQL, SQLAlchemy, Alembic
- Shared cache later: Redis, where justified
- Deployment later: Docker, CI checks, secrets management, monitoring, backups
